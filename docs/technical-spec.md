# Техническое задание (ТЗ) — «Чьё музло?!» (MVP)

## 1. Общее описание

**Название:** Чьё музло?!
**Жанр:** Социальная пати-игра / музыкальная дедукция.
**Аудитория:** Компании друзей (3+ человек), неформальные посиделки.
**Философия:** «One-night stand» — прогресс между сессиями не сохраняется, вся ценность в эмоциях здесь и сейчас.

## 2. Роли и платформы

| Роль | Платформа | Установка |
|------|-----------|-----------|
| Хост | Веб-PWA (Chrome на Android) | Опционально — иконка на главный экран |
| Гости | Тот же веб-PWA в мобильном браузере | Нет (по QR/ссылке) |

## 3. Игровой цикл

1. **Лобби.** Хост открывает приложение → «Создать игру» → генерируется 4-значный код и ссылка; хост показывает QR.
2. **Подключение.** Гости сканируют QR или вводят код, вводят ник, попадают в лобби (комната на локальном сервере).
3. **Сбор контента.** Каждый отправляет ссылку(и) на **трек** Яндекс Музыки. Система помнит, кто что отправил. Плейлисты/альбомы в MVP не принимаются.
4. **Настройка партии.** Хост выбирает длительность (15/30/60 мин). Расчёт треков: `1 трек ≈ 1 минута`.
5. **Раунд** (для каждого трека в случайном порядке):
   - играет отрывок **15–30 сек С НАЧАЛА трека** (звук — только на устройстве хоста, через iframe ЯМузыки в браузере);
   - у всех открывается экран голосования (аватары/ники всех игроков);
   - игроки выбирают, кто скинул трек;
6. **Раскрытие и скоринг:**
   - показываются обложка, название, исполнитель (через iframe-эмбед ЯМузыки);
   - генерируется ироничный комментарий по результатам;
   - начисляются очки по правилам §5.
7. **Финал.** После лимита треков — итоговый экран. Состояние комнаты прекращает публиковаться, данные исчезают.

## 4. Математика треков

- Отрывок: **с начала трека**, длина `∈ [15, 30]` сек (равномерно случайно), задаётся таймером хоста.
- `tracksForDuration(minutes) = round(minutes)`.
- Раунд: `15–30с` аудио + `15с` голосование + `15с` итоги ≈ 60с.

> Случайная точка трека невозможна без неофициального API — по решению заказчика играем с начала.

## 5. Правила начисления очков (строго)

Пусть:
- `N` — количество игроков в партии;
- `Q` — количество игроков, угадавших автора трека;
- `authors` — игроки, отправившие данный трек (может быть несколько — дубликаты ссылок);
- `votes[p]` — за кого проголосовал игрок `p` (или `null`, если не успел).

**Правильное угадывание** = игрок `p` проголосовал за игрока `a`, где `a ∈ authors`.

| Условие | Определение | Результат |
|---|---|---|
| **1** | Угадали **только авторы** трека (даже если авторов несколько) | **0 очков всем** |
| — (вывод) | Никто не угадал | **0 очков всем** |
| **2** | Иначе (есть хотя бы один угадавший не-автор) | Каждый **угадавший** получает `Math.floor(N / Q)`; неугадавшие — **0** |

> Ключевое отличие от старой версии: очки получают **только те, кто угадал**, а не все игроки. Пул равен числу игроков `N`.

См. реализацию: `shared/src/scoring.ts`.

## 6. Интеграция с Яндекс Музыкой (без неофициального API)

- Хост логинится в Яндекс Музыку под своим аккаунтом в браузере (Chrome на Android).
- Приложение работает **только со ссылками**: разбирает ссылку на трек (`/track/{id}`, `/album/{aid}/track/{tid}`) и строит URL официального плеера.
- Воспроизведение: iframe трека, хост жмёт Play, таймер отсчитывает 15–30 сек.
- Раскрытие: iframe-эмбед `https://music.yandex.ru/iframe/#track/{trackId}/{albumId}` показывает обложку/название/исполнителя.
- Название/исполнитель для комментария — из текста шаринга игрока; fallback — «этот трек» + iframe визуально.

См. реализацию: `shared/src/links.ts`.

## 7. Синхронизация

- **Локальный хост-сервер** (`server/index.mjs`) + **WebSocket** — состояние комнаты, фазы, голоса, итоги. Без внешних сервисов.
- Хост — авторитетный клиент (ведёт фазы и таймеры), гости читают/пишут через WebSocket.
- Аудио по сети **не стримится** — играет только на устройстве хоста.

## 8. Визуальный стиль (Vibe)

- Мемный, абсурдный, ироничный.
- Шрифты: жирные комиксные / намеренно «кривые» (аналог Impact / рукописные).
- Цвета: кислотные, неоновые акценты на тёмном фоне.
- Анимации: преувеличенные (тряска экрана при угадывании, летящие эмодзи).

## 9. Нефункциональные требования (MVP)

- Комната до 12 игроков.
- Синхронизация UI < 1 сек (WebSocket по локальной сети).
- Данные комнаты живут только на время партии; после финала состояние перестаёт публиковаться.
- Адаптив под мобильные экраны 320–480px ширины.
- PWA: манифест, офлайн-оболочка не обязательна (игра требует сеть).

## 10. Объём MVP (что НЕ делаем)

- Аккаунты, авторизация, БД, рейтинги, статистика.
- Многопользовательское аудио-стримминг.
- Плейлисты и альбомы (нужен API для разложения).
- Spotify/Apple Music.
- Случайная точка трека (нужен API).

## 11. Определение готовности MVP (Definition of Done)

- [ ] Хост создаёт комнату, видит QR и код.
- [ ] 3+ гостей подключаются по коду/QR и видят общий лобби.
- [ ] Ссылки на треки принимаются и валидируются; плейлисты отклоняются.
- [ ] Отрывок (с начала, 15–30 сек) играет на хосте, фазы синхронны.
- [ ] Голосование синхронно у всех, таймер общий.
- [ ] Раскрытие с iframe + комментарий + корректный скоринг по §5.
- [ ] Итоговый экран, затем комната удаляется.
