# Архитектура «Чьё музло?!» — MVP

## 1. Стек

| Слой | Технология | Почему |
|------|-----------|--------|
| **Приложение (всё в одном)** | **Vite + React + TypeScript**, PWA + **Capacitor** (APK) | Одно приложение на хоста и гостей; открывается в браузере или ставится как APK. |
| **Синхронизация** | **публичные MQTT-брокеры** (WSS) | Комнаты и мгновенный пуш **без аккаунтов, ключей и своего сервера**. |
| **Общая логика** | `@muzlo/shared` (чистый TS) | Скоринг, комментарии, парсер ссылок, движок. |
| **Музыка** | официальный iframe Яндекс Музыки | Хост логинится в браузере; приложение работает только со ссылками. |
| **Хранение** | нет | «One-night stand»: состояние живёт только во время партии. |

## 2. Ключевые решения

1. **Одно приложение** — хост и гости используют один и тот же PWA/APK, различаются ролью.
2. **Ноль настройки** — вместо Firebase используется публичный MQTT-брокер. Никаких ключей.
3. **Без `yandex-music-api`** — только парсинг ссылок + iframe официального плеера.
4. **Отрывок** — с начала трека, 15–30 сек задаёт таймер хоста (случайная точка без API невозможна).
5. **Только ссылки на треки** (плейлисты/альбомы не принимаются).
6. **Звук только у хоста** — телефон хоста играет в колонку, гости видят синхронный UI.

## 3. Поток данных (MQTT)

```
Топики на комнату {code}:
  muzlo/{code}/state   ← хост публикует снимок (retained)  → гости читают
  muzlo/{code}/join    ← гость: { playerId, nickname }
  muzlo/{code}/track   ← гость: { playerId, clientTrackId, text }
  muzlo/{code}/vote    ← гость: { playerId, votedForId }
```

- **Хост** — авторитет: держит `GameEngine`, ведёт фазы и таймеры, публикует `state` (retained), слушает «намерения» гостей.
- **Гости** — читают `state`, шлют `join/track/vote`.
- **Retained** даёт опоздавшему гостю актуальный снимок сразу после подписки.

### Устойчивость

Публичные брокеры бывают нестабильны, поэтому:
- **Хост** подключается ко **всем** брокерам из списка и транслирует состояние во все, слушая намерения на всех.
- **Гость** подключается к **первому доступному**.
- Так игроки встречаются, даже если у кого-то один брокер недоступен.

Список брокеров — `app/src/sync.ts` (`BROKERS`), можно поменять в одном месте.

## 5. Тайминги раунда (крутит хост)

```
start() → beginRound (iframe трека)
   └─ setTimeout(15–30с) → openVoting()
         └─ setTimeout(15с) → reveal()   (очки + комментарий)
               └─ setTimeout(15с) → nextRound()  (или finish)
```

## 6. Вход в Яндекс Музыку

- Хост логинится в Яндекс Музыку в браузере.
- В раунде встраивается iframe трека; хост жмёт Play. Звук слышит вся комната.
- Если iframe не играет — ссылка «Открыть трек в Яндекс Музыке».

## 7. Ограничения и риски

- **Публичный брокер** — не гарантирует 100% uptime; для личного использования приемлемо. При желании легко заменить на свой MQTT/WebSocket-сервер.
- **Без auth** — кто знает код комнаты, может повлиять на игру. Для дружеской вечеринки ок.
- **Случайная точка трека** недоступна без API.
- **Название/исполнитель** для комментария — из текста шаринга; иначе «этот трек».
