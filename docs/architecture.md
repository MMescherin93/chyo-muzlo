# Архитектура «Чьё музло?!» — локальная комната

## 1. Стек

| Слой | Технология | Почему |
|------|-----------|--------|
| **Хост-сервер** | **Node.js + `ws`** (`server/index.mjs`) | Раздаёт приложение и связывает хоста с гостями по WebSocket. Всё в одной Wi-Fi, без внешних сервисов. |
| **Клиент** | **Vite + React + TypeScript** | Один и тот же UI для хоста и гостей; хост и гости — просто роль в комнате. |
| **Логика** | `@muzlo/shared` (чистый TS) | Очки, комментарии, разбор ссылок, движок. Выполняется в браузере хоста. |
| **Музыка** | iframe Яндекс Музыки + ссылка в новую вкладку | Хост — единственный, кто играет звук. |
| **Хранение** | память сервера | «One-night stand»: комната живёт только пока запущен сервер. |

## 2. Ключевые решения

1. **Комната на одном устройстве.** Хост запускает `npm run host`; сервер раздаёт приложение и держит WebSocket. Гости заходят по ссылке `http://<LAN-IP>:8080`.
2. **Без интернета и внешних сервисов.** Нет MQTT/Firebase/облака — только локальная сеть.
3. **Хост — авторитет.** Движок (`GameEngine`) и таймеры живут в браузере хоста. Сервер — тонкий релей.
4. **Только ссылки на треки** (плейлисты/альбомы не принимаются).
5. **Звук только у хоста.** Звук идёт из колонок компьютера; гости видят синхронный UI.

## 3. Поток данных (WebSocket-релей)

```
      ┌────────────── server/index.mjs ──────────────┐
      │  rooms: { host, guests:Set, state }           │
      └───────▲───────────────────────────┬──────────┘
              │ state                     │ state
              │                           │
        ┌─────┴─────┐               ┌─────▼─────┐
        │   Хост    │               │  Гости    │
        │ GameEngine│               │  UI       │
        └─────┬─────┘               └─────▲─────┘
              │ intent                    │
              └───────────────────────────┘
```

Протокол (JSON по `/ws`):

| От | Сообщение | Смысл |
|---|---|---|
| Хост | `{t:'host', room}` | зарегистрироваться хостом комнаты |
| Гость | `{t:'guest', room}` | войти в комнату; сервер сразу шлёт последнее `state` |
| Хост | `{t:'state', room, data}` | опубликовать снимок комнаты (кэшируется и рассылается гостям) |
| Гость | `{t:'intent', data}` | намерение: `join` / `track` / `vote` |
| Сервер | `{t:'state', data}` | гостям |
| Сервер | `{t:'intent', data}` | хосту |
| Сервер | `{t:'host-gone'}` | гостям, если хост отключился |

- **Хост** держит `GameEngine`, ведёт фазы/таймеры и рассылает `state`.
- **Гости** читают `state` и шлют `intent`.
- **Поздний гость** сразу получает последнее состояние — сервер его кэширует.

## 4. Тайминги раунда (крутит хост)

```
start() → beginRound (iframe трека)
   └─ setTimeout(15–30с) → openVoting()
         └─ setTimeout(15с) → reveal()   (очки + комментарий)
               └─ setTimeout(15с) → nextRound()  (или finish)

Кнопка «Хватит слушать» → forceVoting() (досрочно)
```

## 5. Локальная сеть и QR

- Сервер слушает `0.0.0.0:8080`.
- `GET /api/info` возвращает LAN-адрес (`http://192.168.x.x:8080`), поэтому QR ведёт на правильный адрес, даже если хост открыл `localhost`.
- Гости должны быть в той же Wi-Fi; Windows Firewall должен пропускать Node.js.

## 7. Ограничения

- **Плеер Яндекс Музыки** — iframe работает нестабильно; есть кнопка «Открыть в новой вкладке». Полные треки — при входе в Яндекс (иначе 30-сек превью).
- **Случайная точка трека** недоступна (нет API).
- **Хост должен держать сервер запущенным** — он и есть комната.
- `app/android/` и APK — **устаревший путь**, новой модели не нужны.
